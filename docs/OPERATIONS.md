# 品牌、音樂內容與 LINE 運營

目標是讓作品被聽見、歌迷能追蹤消息、活動主辦能找到邀約入口。這個版本提供保存資料、完整提示詞與工作單；不會替使用者開 LINE 帳號、發送訊息或自動發布。

## 第一次設定

1. 到「設定」填品牌名稱、業務、受眾與使用平台。
2. 到「品牌與運營」填目標、定位、聲音試聽紀錄、作品故事、視覺、字幕與剪輯規格。
3. 在「來源、帳號用途與授權」逐項記錄 `來源網址｜個人或團隊｜狀態｜可用範圍｜核對日期`。能公開觀看不等於能重製、廣告投放或商用。
4. 儲存後開啟品牌、剪輯、LINE 或每週 Agent 工作單。沒有金鑰時複製提示詞；有金鑰才會送到自行選定的 AI 服務。
5. 下載手冊交接給剪輯與營運；手冊只取已儲存資料。換裝置前下載備份。

每個文字欄位最多 2,000 字；長篇原始資料另存自己的資料夾，在欄位記摘要與連結。欄位完整度只是填寫進度，人工勾選也只是紀錄，不代表系統查證通過。

## 兩條內容路徑

| 目的 | 素材 | 下一步 | 衡量 |
| --- | --- | --- | --- |
| 新歌曝光 | 授權副歌、故事、教唱亮點 | 聽完整版、追蹤或訂閱，一支只選一個 | 觀看留存、完播、分享、個人頁造訪、淨增粉絲 |
| 活動邀約 | 授權舞台片段、主持與流程示例 | 官方 LINE 的「活動邀約」 | 有效詢問、資料完整率、回覆時間、確認場次 |

婚宴、企劃活動、主持、歌唱比賽、評審、廟宇慶典都可作為需求分類。實際能承接的服務、過往案例、檔期及報價需由本人或團隊確認。

## LINE：先半自動，再串接

依 [LINE 官方建立說明](https://developers.line.biz/en/docs/messaging-api/getting-started/)，先建立官方帳號，需要程式串接時再啟用 Messaging API。現有私人對話以邀請連結引導自願加入，這個產品不會搬移私人好友或聊天紀錄。

六格選單建議：聽新歌、看演出、關於我、活動邀約、學唱歌、聯絡團隊。先用官方後台設定歡迎訊息及關鍵字回覆，真人每日處理待回覆清單。主動推播依地區方案與額度規劃，查 [LINE 官方計價說明](https://developers.line.biz/en/docs/messaging-api/pricing/)；不要把日本方案數字當台灣價格。

邀約收件：活動類型、日期、時段、地點、希望的服務、預估流程、聯絡方式。缺資料只補問，不承諾可接；真人確認 → 檔期卡 → 報價 → 流程確認 → 前日提醒 → 結案。聯絡與報價留在私人對話，不貼到公開文案或 GitHub。

後續自動化架構：`LINE webhook → 驗證原始請求簽章 → 事件去重 → 意圖分類 → 已核對 FAQ 或邀約草稿 → 真人接手 → 稽核紀錄`。先做 [簽章驗證](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/)，再處理事件；金鑰放伺服器秘密設定。收到取消通知、封鎖或交接真人後，停止該類自動跟進。檔期、報價、合約與公開發布保留人工決策。

## 每週 Agent 工作流

| 階段 | 輸入／產出 | 技能 | 交接條件與失敗處理 |
| --- | --- | --- | --- |
| 研究核對 | 官方資料 → 可追溯品牌摘要 | `music-operations` | 帳號與經歷未核對就標待確認，不能當文案事實 |
| 素材整理 | 原片、歌詞、授權 → 素材清單與時間碼 | `music-operations` | 無原片或授權就列待補，不擅自下載別人影片 |
| 製作 | 剪輯單 → 短片、字幕、封面、文案草稿 | `music-engine`、`site-ai-prompts` | 自動選段與歌詞對位需人工驗收，不保證自動字幕正確 |
| 審核 | 草稿 → 核准版本 | `site-review`、`site-test` | 核對字詞、來源、隱私、音質、人物與使用權，失敗退回製作 |
| 半自動發布 | 核准版本 → 平台排程與 LINE 草稿 | `music-operations` | 人到平台確認發布；邀約送真人核檔與報價 |
| 回顧 | 平台後台與邀約紀錄 → 下一週實驗 | `music-operations` | 沒數據記未知，與同平台、同長度及同觀測期間比較 |

這是可交給 AI 和人協作的流程。現有 GitHub 剪輯工作流仍需依 `MUSIC-ENGINE.md` 設定；本次新增的工作單本身不會啟動 Actions 或外部 Agent。不要把公開 issue 當未公開素材的交件處，現有剪輯工作流會把成品發到 Releases，啟動前確認分享範圍。

## 驗證

`npm test` 驗證本機保存、惡意文字呈現、好友連結驗證、四種提示詞、備份搬家與手機／桌機淺深色。設定 `APP_URL=http://127.0.0.1:8787/` 可對全新的本地雲端測試環境執行同套流程；測試會建立測試密碼與資料，請勿對正式站執行。截圖預設放系統暫存目錄，可用 `SCREENSHOT_DIR` 指定。

真實 AI 回覆、LINE 發送、平台發布及私人素材聽感需要已授權的帳號、金鑰或原片，不能由這套離線測試證明。

## 不下載檔案的個案配置

經使用者授權的個案放在 `campaigns/`；網站的「內建運營包」可直接套用。先確認更新範圍，品牌欄位依包內配置更新，未指定的設定保留；相同 ID 草稿保留修改。資料來源為 `catalog.json` 與各包的 `profile.json`，執行既有同步腳本即可產生兩版 `campaigns.js`，不增加建置步驟。

專屬網址的 `campaign` 參數僅在尚未填寫品牌、尚無內容及金鑰的工作區自動套用。已填寫的工作區不自動覆蓋，請到內建運營包按鈕確認。GitHub Pages 版每個瀏覽器各自儲存，不是多人共用的雲端資料庫。
