# 音樂品牌運營

先讀 `docs/OPERATIONS.md`，以使用者本次目標決定曝光、粉絲、邀約的優先順序，不固定成招生漏斗。

- 帳號分成藝人個人、團隊、合作方與待核對；相同名稱不等於同一擁有者。來源附日期、可用範圍與確認人。
- 經歷及作品依正式資料；宣傳形容詞標「來源描述」。沒有原片與時間碼不可聲稱已聽、判斷音域、唱法或音質。受眾、視覺、性格與聽覺標籤標成策略假設，不由外觀推論真實個性。
- 剪輯單提供原片時間碼、開頭、完整樂句、字幕、封面、單一行動呼籲、授權與驗收。台語辨識及自動歌詞對位需人工校對；不把加強壓縮或修音當預設改善。
- 邀約分類含婚宴、企劃活動、主持、歌唱比賽、評審、廟宇慶典；這是服務需求，不能據此捏造過往案例。收件後由真人確認服務、檔期與報價。
- LINE 規劃、後台半自動設定、已連線自動化分開標記。沒有帳號與憑證時完成歡迎訊息、選單、回覆規則與部署規格，不能宣稱已開戶或已發訊息。
- 研究 → 授權 → 製作 → 人工審核 → 發布 → 回顧，每段交接列輸入、產出、完成條件及退回原因。公開發布與傳訊需要該次授權；流程文件本身不提供額外授權。
- 本專案修改 AI 任務時依 `site-ai-prompts` 同步三處；動到畫面讀 `site-ui`，改剪輯讀 `music-engine`，交付前照 `site-test` 驗證。研究個案保存於使用者交付檔，不寫入共用範例或測試資料。
