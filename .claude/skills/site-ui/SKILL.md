# 介面與體驗規範

## 設計基調
後台工作工具：清楚、溫暖、按得到。品牌色由使用者在設定選（CSS 變數 `--brand`），整個網站跟著變；**不要寫死顏色**。

## 顏色變數（app.css）
- `--red`：品牌色（主要按鈕、選中狀態）。`--hl`：品牌色的「文字用版本」，深色模式會自動變亮；**文字、連結、標籤一律用 `--hl`**，不要用 `--red` 當文字色。
- `--bg` 底色、`--panel` 區塊底、`--pink` 品牌淡色、`--line` 邊線、`--ink` 字、`--mute` 次要字、`--green`／`--gtint` 完成。
- 狀態標籤：`s-wait`（待剪輯、剪輯中，中性灰）、`s-act`（待審核，需要動作，品牌色）、`s-plan`（已排程，藍）、`s-done`（已發布、已結案，綠）。一個畫面只讓「需要動作」的東西用強調色。

## 字與排版
- 標題 Noto Sans TC 900，數字 Outfit。內文 16px，最小 13px。
- 每頁結構：`.top`（h1＋一句說明＋主要按鈕）→ 內容。h1 加 `tabindex="-1"`（換頁時焦點會移過去）。
- 列表與卡片一定要有容器（`.panel` 或 `.card`），不能是裸文字。

## 元件（直接用，不要自創）
`.btn`（主要）、`.btn.ghost`（次要）、`.btn.quiet`（低調，如刪除入口）、`.btn.danger`（只在確認對話框）、`.chip`（篩選與勾選）、`.tag`、`.panel`、`.card`、`.empty`（空狀態，要附一個下一步按鈕）、`.drop`（拖放上傳）、`.progress`、`confirmBox()`、`fieldError()`、`toast()`。

## 文字語氣
- 按鈕用動詞開頭，說清楚結果：「放進待剪輯」「刪除影片卡」，不要「確定」「送出」。
- 錯誤訊息說怎麼解決，不責怪使用者：「請寫一個標題，方便之後找到這支影片」。
- 不用工程術語（API、JSON、資料庫）對使用者說話，除非在「設定 → AI」這種必要處。

## 互動規則
- 刪除等無法復原的動作：`confirmBox()`，標題寫出名稱，按鈕寫「刪除＋名詞」。
- 表單：送出時檢查，錯誤顯示在欄位下方（`fieldError`），使用者一改就消失。
- 存檔後給回饋（`patch` 的 `note` 或 `toast`）。
- 動畫只用 `transform`、`opacity`；`prefers-reduced-motion` 時關掉。

- [ ] 淺色、深色模式都清楚可讀（深色下文字不能用 `--red`）。
- [ ] 每個輸入框都有看得到的標籤或 `.sr` 標籤；圖示按鈕有文字。
- [ ] 鍵盤能操作全部功能，焦點看得到。
- [ ] 空狀態、載入中、錯誤三種情況都有畫面。
