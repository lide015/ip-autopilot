## 音樂定位、聲音與故事

音樂資料支持台語歌曲與抒情作品路線。唱片介紹使用渾厚、感染力等描述；這些屬來源的宣傳描述，不能替代聽感測量。[唱片資料](https://www.ccr.com.tw/goods/434411)

本次沒有取得可處理的授權音訊，未直接試聽、分析音域、共鳴、氣息、顫音或現場穩定度。建議先測試三個聽覺標籤：**台語情感、溫暖厚度、真誠敘事**。〈聖母媽祖〉另加作品層標籤「感恩、守護、祝福」，與全品牌標籤分開。

試聽工作表：每首取主歌、情緒推進、高潮、收尾各一段，填 `檔案／正式來源｜時間碼｜咬字｜明暗與厚薄｜力度與動態｜適合場景｜試聽人｜日期`。錄音室及現場版本分開比較，不能以伴奏音高推定歌手全部音域。

作品入口建議：〈聖母媽祖〉作本波主推；〈感情冊〉作情感作品入口；〈掌上明珠〉作婚宴需求的曲目候選；〈雨水恰恰〉作歡樂場景候選；〈雨傘下〉作合作作品入口。這是內容選曲建議，非依後台排名判定的「最紅代表作」。曲目與歌詞使用權需確認。

故事以「為什麼選擇唱這首歌」「想把祝福唱給誰」「從教唱到舞台的感受」三條線採訪。宗教體驗採本人敘述並經確認；家庭與健康故事須另獲本人同意，避免把情感或信仰敘事寫成療效保證。

## 視覺、人設、字幕與剪輯

人設採「溫暖的歌手、親切的老師、可靠的舞台夥伴」作公開表達方向，需本人認可，不據此判斷私下性格。

| 用途 | 視覺與聲音建議 |
| --- | --- |
| 〈聖母媽祖〉 | 米白、暖金、深紅少量點綴；臉部近景、舞台與文化場景。莊重、有空間，取樣時保留完整情緒 |
| 婚宴與企劃活動 | 沿用人物與字體識別，換成合適的喜氣或明亮場景；呈現互動、入場、控場與流程配合 |
| 主持與評審 | 清楚的人聲、可理解的說明、現場反應。未取得案例前先拍服務介紹，不用假活動照片 |

直式主檔沿用引擎 1080×1920、30fps。字幕起始建議：Noto Sans TC／思源黑體，白字搭深描邊，通常一至兩行、每行約8–12個中文字；實際依手機可讀性調整。主字約56–68px，封面8–12字。先預留左右約90px與底部約300px，再到各平台預覽確認按鈕、說明與人物沒有遮擋；這些是工作起點，不是平台永久安全區規格。

台語歌詞由權利方提供並人工校字；對位依樂句及原片，不以華語辨識結果直接上線。祈願短句、歌詞與人物姓名分層排版；不使用整畫面快速逐字跳動遮住演唱表情。

三種剪輯單：

1. **副歌情感版20–35秒**：前兩秒進入最能傳達情感的畫面，保留完整樂句，結尾引導聽完整版。時間碼待授權原片選段。
2. **故事／教唱版30–45秒**：先講一句想傳達的心意，再帶演唱；結尾問觀眾想把祝福送給誰。需本人錄製或核准的訪談。
3. **舞台邀約版15–25秒**：用合適現場與清楚的人聲呈現舞台氛圍；結尾活動邀約入口。廟宇、婚宴、主持等素材分開匹配，不用一支片承諾所有服務。

原始音檔先留備份。正式混音不預設再套重降噪、重壓縮或人聲分離；手機現場音再依底噪、爆音與動態判斷。現有引擎有處理鏈，必須做原音／處理後比較，不能把「更大聲」等同「更好聽」。本次未改音訊引擎或產出真實成片。

## 自動化與半自動化工作流

**現在可做**：以本產品保存定位與規格、整理提示詞及內容卡；在官方後台設定回覆；真人審核後到平台發布。這次交付的是可使用的規劃工具與配置，尚未建立真實 LINE 帳號、未連接發送服務。

**官方帳號開好後**：事件進來 → 伺服器驗證簽章 → 以事件ID去重 → 辨識新歌／演出／教唱／邀約 → 已核對資料自動回覆或產草稿 → 真人處理檔期、報價與合約 → 記錄結果。未核實資訊回「待確認」，不自動答允。取消通知或轉真人後停止自動跟進。[簽章驗證](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/)、[Webhook處理](https://developers.line.biz/en/docs/messaging-api/receiving-messages/)

帳號秘密放伺服器，不能放GitHub公開檔或品牌備份。原片、人名、電話及報價用團隊自己的私有工作區；目前GitHub剪輯工作流會把成品發到Releases，啟動前要確認公開範圍。

| Agent階段 | 輸入 | 可驗收產出 | 人工關卡／失敗處理 |
